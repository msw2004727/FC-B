# 審查避坑規則（由第三方審查 findings 整理）

## 非同步與競態

- **L-01**：遠端旗標／註冊表變更後，路由與導覽必須以同一份版本化快照重算，不得只在初次掛載時計算一次。理由：旗標更新不發佈狀態時，舊路由仍可觸發載入，導覽與路由會不一致。
- **L-02**：語系切換等非同步載入後提交狀態前，先比對遞增請求序號，過期結果只寫快取不改公開狀態、不發事件。理由：先選 A 再選 B 但 A 較晚完成時，字典、`lang`、偏好與複數規則會互相錯配。
- **L-03**：一次切換中語系、字典、`html lang`、儲存偏好與通知必須在同一次同步提交，不得先改語系再等字典。理由：分步提交會產生「新語系搭配舊字典」的中間狀態。
- **L-04**：hook 先在 render 讀值、effect 才訂閱時，訂閱後必須補讀一次目前值。理由：render 與 effect 之間的變更會漏接並保留舊值。
- **L-05**：App 級更新時不得每次 render 都新建 `lazy()` 元件型別；依穩定 loader／route 身分快取。理由：新的元件型別會造成不必要重掛載與頁面狀態重置。
- **L-06**：切詞器等 per-locale 重型物件每語系重用，靜態詞表預先排序一次。理由：每次文字處理重建 Segmenter 或重排詞表是重複成本。
- **L-07**：呼叫 `void promise` 視同未處理拒絕，須改為 `catch`／`try` 並明確處理。理由：`void` 不會處理 Promise 拒絕，錯誤會無聲流失。

## 錯誤處理與復原

- **L-08**：inflight／進行中請求 Map 必須在成功與失敗兩條路徑都清除。理由：失敗 Promise 留在 Map 會永久污染快取，同頁重試只取得同一個拒絕。
- **L-09**：非同步載入失敗時保留上一份完整狀態（含字典、`lang`、選單一致），並提供可理解的重試提示。理由：失敗後切換到空字典會顯示翻譯 key，UI 狀態互相矛盾。
- **L-10**：錯誤邊界的錯誤狀態必須隨路徑變更而重設（例如以路徑為邊界 key），同路徑才保留重試。理由：只在 `handleRetry()` 清錯誤會讓回首頁與 BottomNav 導覽停留在錯誤畫面。
- **L-11**：路由內容與外框要分層錯誤邊界：路由邊界保留外框與返回入口，外層另設整體故障保護。理由：單一邊界涵蓋整個外框會擴大故障影響範圍。
- **L-12**：事件處理與獨立非同步 Promise 的錯誤要自行捕捉，不能期待 ErrorBoundary 代為處理。理由：此類錯誤不會進入 render 錯誤邊界。
- **L-13**：啟動各階段錯誤要有保護與可讀錯誤畫面；註冊提交前以 DFS「未訪問／訪問中／已完成」驗證依賴圖，拒絕循環並列路徑。理由：無保護的遞迴依賴會堆疊溢位，註冊失敗會留下空 `#app`。
- **L-14**：註冊／啟動失敗不得留下部分資料，全部驗證完成才提交。理由：部分提交後狀態不一致，重試也無法恢復。
- **L-15**：emit 時逐一隔離 listener 例外，快照後逐個呼叫並記錄錯誤。理由：單一 listener 丟錯會阻止後續訂閱者更新，削弱功能彼此獨立。
- **L-16**：定義並測試 emit 期間新增／移除 listener 的快照語意（移除者仍收本次事件）。理由：快照語意易被誤判成迭代 bug，需契約測試保護。

## 狀態訂閱與重繪

- **L-17**：所有跨元件顯示狀態（主題、旗標、語系）走共用 hook／訂閱機制，不得個別同步讀值。理由：只同步讀取主題的頁面不會隨 `theme:updated` 更新顯示文字。
- **L-18**：旗標變動的 key／重設機制只針對需重設的錯誤邊界，不得以註冊表版本當路由 key。理由：旗標變動會重掛載仍啟用的正常頁面並丟失其狀態。

## i18n

- **L-19**：語系解析要依語言、文字系統、地區子標籤判斷，中文優先 `Hant`／`Hans`，並在 extension／private-use 起點停止掃描。理由：只比對完整字串會漏 `zh-Hant-TW`；掃描全部子標籤會把 extension 值 `hans` 誤當 script。
- **L-20**：i18n 檢查器要驗證包括基準語系在內的每個語系根結構與葉節點（拒絕空字串、非字串、null）。理由：基準字典被 `continue` 略過時，壞值不會被拒絕。
- **L-21**：功能契約要求的每個語系目錄與必要 key 要逐一核對，目錄探測失敗不能靜默略過。理由：整個功能 `locales/` 缺失仍可能檢查成功。
- **L-22**：比對各語系插值參數集合，並拒絕攤平後 key 衝突。理由：key 一致不代表內容可用，參數不同會造成執行期插值失敗。
- **L-23**：測試語系解析時不得只測與預設值相同的結果。理由：`zh-Hant-TW` 假陽性測試因預設值也是繁中而誤過。

## 換行與 Text

- **L-24**：先定義「超長詞是否允許緊急拆分」的政策，再決定 CSS／渲染單位；文件不得宣稱絕對不拆詞除非實作不可分割渲染單位。理由：`overflow-wrap: break-word` 允許緊急拆分，宣稱與實作不符。
- **L-25**：降級詞表要補齊各語系（簡中、日文等），不只繁中。理由：無原生 Segmenter 時其他語系長段落主要依賴緊急斷行。
- **L-26**：代碼／長詞識別要先辨識完整代碼再判長度上限，避免保留過短前綴匹配。理由：`matchCodeEnd()` 可能把完整代碼的較短前綴包成 `.ui-nobr`。
- **L-27**：換行、禁則與 nowrap 效果要以真實瀏覽器行盒／截圖驗證，不能只數 `<wbr>`。理由：`<wbr>` 數量與 `.includes()` 斷言不能證明實際不拆詞。
- **L-28**：「文字一律使用 `<Text>`」要明列例外（原生 `<option>`、無障礙標籤、placeholder 等），新例外需補文件。理由：未列例外時實作者會在兩種不合規做法間猶豫。

## 測試寫法

- **L-29**：非同步競態測試要用可控制完成順序的 Promise，覆蓋快速連續切換、快取命中與網路請求交錯。理由：正常路徑測試無法涵蓋競態與失敗復原。
- **L-30**：失敗復原測試要模擬「第一次拒絕、第二次成功」並驗證重新呼叫 loader。理由：僅驗快取參照相等不能證明去重與重試行為。
- **L-42**：頁面載入 `preact/compat`（例如 Modal 的 `createPortal`）後，`@testing-library/preact` 的 `fireEvent.change` 會改送 `input` 事件；`<select>`、checkbox 的 onChange 仍聽原生 change，必須在 `act` 內以 `element.dispatchEvent(new Event('change', { bubbles: true }))` 派送（checkbox 可用 `fireEvent.click`）。理由：否則 handler 從未執行，測試誤判為元件 state 錯誤。

## 資料完整性與權限

- **L-31**：快取／API 正規化格式與 Firestore 儲存格式必須分開描述，快取 shape 不授權改寫儲存格式。理由：混用會改變與 A 共用的資料格式並破壞空陣列語意。
- **L-32**：Write 型別不得等於完整讀取文件，不得附索引簽名；按動作（建立、編輯、已讀等）拆專用 payload 並在資料存取層做欄位 allowlist。理由：照 `XxxWrite = XxxDoc` 實作仍能寫入契約禁止的欄位。
- **L-33**：FieldValue／`serverTimestamp()` 只套用到逐動作欄位表列出的欄位，不得「一律」套用到所有時間欄。理由：歷史時間欄被改寫會影響排序、候補與統計。
- **L-34**：經驗值等日誌集合若只有 server 寫入證據，B 不得直寫，調整走既有 Callable 並保留去重。理由：重複建日誌會造成日誌與餘額不一致。
- **L-35**：業務動作要對照「既有端點 → 原子副作用」，無既有通道者標為不支援，不得以直寫補救。理由：只改容量不同步報名狀態會破壞原子性並產生半完成狀態。
- **L-36**：身份欄位（uid／actorUid／creatorUid）依動作分別取操作者、所屬者、建立者，不得一律取目前登入者。理由：管理者代操作時會把對象 UID 寫成管理者 UID。
- **L-37**：規範、觀察證據、推測要分開標示；截斷的 Rules 摘要不能寫成完整允許條件，未知父路徑保持未解析。理由：截斷片段與 `?` 被當成完整規則會導致誤信授權或誤判 drift。
- **L-38**：資料可讀取不等於產品允許顯示，可見性過濾與 effective permission 要納入查詢與 UI 判斷。理由：未過濾會顯示不應顯示的活動、錯擋同行者或放寬管理權限。
- **L-39**：路徑常數要與目錄、Rules 交叉校對；ID 與 idempotency key（如 `clientRequestId`）不得互相替代。理由：錯集合名與錯父路徑會寫入錯誤位置，重試鍵被當 canonical ID 會破壞資料連結。

## 效能

- **L-40**：字典等啟動資源要區分核心／首屏必要與按頁載入，未啟用功能不列入必要依賴；改動前先量測冷快取瀑布圖。理由：全部功能字典在首次掛載前載入會放大冷啟動成本。
- **L-41**：效能宣稱（gzip 大小、chunk 數）要以正式建置產物佐證，不以 loader 呼叫次數代替請求數。理由：`manualChunks` 可能合併 chunk，loader 次數與 HTTP 請求數不一定相等。
