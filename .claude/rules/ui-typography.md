# 字級規範（R-UI-032 的具體數值與落實方式）

> 2026-11-17 新增（站長指示、顧問夜誌 §3.228 裁定）。R-UI-032 正本在 FC repo `.claude/rules/ui.md`；本檔是它的具體數值，只放在 FC-B（程式在這裡），FC 那邊只留一行指過來，不另寫一份。
> 可依實際呈現需求調整；調整時直接改本檔，並在改動處寫一行「取代了什麼、為什麼」（R-GOV-007）。
> 適用前台與後台頁面（後台仍維持一般風格、不套液態玻璃，只管字級）。行高、字距暫不規範。

## 1. 字級七級（token 名稱沿用 `src/styles/tokens.css`）

以根字級 15px 換算；使用者可切 15／16.5／18（`src/core/font-size.ts`），所以一律用 rem 才會跟著放大。

| token | 值 | 15px 時約 | 用途 |
|---|---|---|---|
| `--font-size-caption` | 0.8rem | 12px | **全站最小值**：註記、時間、標籤 |
| `--font-size-body-sm` | 0.875rem | 13px | 次要文字、表格內文 |
| `--font-size-body` | 1rem | 15px | 正文 |
| `--font-size-body-lg` | 1.125rem | 17px | 強調文字、卡片標題 |
| `--font-size-title` | 1.25rem | 19px | 區塊標題 |
| `--font-size-title-lg` | 1.5rem | 22px | 頁標題 |
| `--font-size-display` | 1.875rem | 28px | 只給大數字或首頁主視覺 |

- 手機輸入框（`input`、`select`、`textarea`）一律 `max(16px, 1rem)`，避免 iPhone Safari 聚焦自動放大（站長標準 U7）。
- **現況**：tokens.css 這七個值目前仍是 px（11／13／15／17／19／22／28），改 rem 由另一張小卡單獨做（附三種字級下的截圖給顧問驗收）；改完 caption 由 11px 變 12px，其餘差不到 1px。在那之前新程式照樣用 token。

## 2. 粗細三級

- 400 正文、600 強調／卡片標題、700 頁標題。
- 現有的 500 視為「待收斂」（改到時依視覺歸到最接近的 400 或 600），不算違規。
- 300、800 以上禁止新增。

## 3. 落實方式（漸進，不為收斂另開大改）

1. 新寫或改到的元件一律用上表 token，不得新增寫死的 font-size。
2. 改到某個檔案時，同一元件內的寫死字級順手換成最近的 token；小於 0.8rem 的升到 caption。
3. 第 2 點的但書：升級後該元件要附改前改後截圖；若擠壞版面（徽章、頁籤、表格欄位等）造成截字或斷行，就列為例外或改排版，不得硬升。
4. 機器把關：`npm run check` 加只增不減的閘門——統計 src 內寫死 font-size 的處數，高於基準檔就失敗、低於就提示更新基準（基準檔進 repo）。閘門上線前，審查時人工檢查「本次有無新增寫死字級」。
5. 派工卡固定寫：「字級只用 `ui-typography.md` 的 token；改到的元件順手收斂；不得新增寫死字級」。
